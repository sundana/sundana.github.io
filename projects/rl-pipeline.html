Distributed Reinforcement Learning Pipeline for Multi-Agent Coordination

Research Project · 2024–2025

Overview

A production-grade distributed training pipeline for multi-agent reinforcement learning (MARL), designed to train cooperative policies across thousands of parallel environments. The system handles environment simulation, policy inference, experience collection, and model updates at scale, with fault tolerance and dynamic resource allocation.

Architecture

The pipeline follows a decoupled actor-learner pattern inspired by IMPALA and SEED RL, with several key innovations for multi-agent settings:

System Components

  • Rollout Workers — 256 parallel processes each running multiple environment instances. Workers step agents, collect trajectories, and stream (state, action, reward, next_state) tuples to a shared replay buffer via gRPC.
  • Central Replay Buffer — A Redis-backed priority buffer with support for multi-agent trajectory batching. Implements Generalized Advantage Estimation (GAE) as a streaming preprocessing step.
  • Learner — Distributed across 8× NVIDIA A100 GPUs using PyTorch DistributedDataParallel. Supports PPO, SAC, and QMIX algorithms with pluggable policy architectures.
  • Parameter Server — Redis-based model store with versioned weights and rollback capability. Enables hot-swapping policies during training without restarting rollout workers.
  • Orchestrator — Kubernetes-native controller managing worker lifecycle, auto-scaling rollout workers based on buffer pressure, and coordinating graceful shutdown for checkpointing.

Technical Details

Environment & Problem Setting

  • Multi-agent particle environment (MPE) with 4–16 cooperative agents
  • Partially observable setting with agent-specific observation spaces
  • Continuous action space with centralized training, decentralized execution (CTDE)
  • Custom reward shaping for cooperative navigation, predator-prey, and resource collection tasks

Algorithms Implemented

  • MAPPO — Multi-Agent PPO with centralized critic and decentralized actors
  • QMIX — Monotonic value factorization for cooperative MARL
  • MADDPG — Multi-agent deep deterministic policy gradient with attention-based critic

Infrastructure

  • Kubernetes cluster (GKE) with 4 nodes, each 8× A100 40GB
  • Redis Cluster (6 nodes) for replay buffer with 128GB total memory
  • Prometheus + Grafana for monitoring: throughput (steps/sec), buffer pressure, reward curves
  • Weights & Biases for experiment tracking and hyperparameter sweeps
  • Model checkpoints stored in Google Cloud Storage with versioned paths

Results

Throughput

  • Peak throughput: 480,000 environment steps per second across 256 rollout workers
  • Policy inference latency: 2.3ms (batch size 512, A100)
  • Replay buffer write throughput: 1.2M ops/sec on Redis Cluster

Training Efficiency

  • MAPPO converges to 95% of optimal cooperative reward in 12M environment steps (vs. 45M for single-machine baseline)
  • Linear scaling efficiency of 0.92 when scaling from 1 to 8 GPUs for the learner
  • Dynamic worker autoscaling reduced idle GPU time by 34% compared to fixed-pool allocation

Fault Tolerance

  • Graceful recovery from rollout worker failures without training interruption
  • Checkpoint-resume from any step with < 5 second recovery time

Key Engineering Challenges

  1. Stale policy problem — Rollout workers use slightly outdated policies. Addressed with off-policy correction via V-trace, trading a small bias for significant throughput gains.
  2. Uneven environment step times — Different scenarios have heterogenous step durations. Solved with asynchronous worker pools and dynamic batching at the buffer level.
  3. Memory pressure on Redis — Multi-agent trajectories are memory-intensive. Implemented sliding-window eviction with priority retention for high-TD-error transitions.
